# CosmoOS 1.1.3

The project's new home, and upgrades that follow it there.

## The project moved to CeeSafe

The repository is now
[`CeeSafe/CosmoOS`](https://github.com/CeeSafe/CosmoOS), and the site
with the releases and the package repository moved from
`https://vkuttyp.github.io/CosmoOS/` to
`https://ceesafe.github.io/CosmoOS/`. The old address still serves the
same files, so a system installed before the move keeps working.

From this release:

- `cosmo-upgrade`, `cosmo-install` and `/etc/cosmo-release.conf` name the
  new address.
- This release's `cosmo-upgrade` moves the old address to the new one
  in `/etc/pkg/repos.conf` and `/etc/cosmo-release.conf` when it upgrades,
  and says so:

  ```text
  cosmo-upgrade: /etc/pkg/repos.conf: the project's address moved to https://ceesafe.github.io/CosmoOS/
  ```

  An upgrade never replaced `repos.conf`'s `cosmoos` line, which
  `cosmo-install` wrote, so without this move the system would have
  stayed on the old address.

## Upgrading from v1.1.2

**Run `cosmo-upgrade --fetch v1.1.3` twice, then reboot.** The first run
is v1.1.2's own `cosmo-upgrade`, which installs the release, the new
`cosmo-upgrade` among it, but does not know the move. The second is the
new one: it finds the release already installed, finishes, and moves the
address:

```text
cosmo$ cosmo-upgrade --fetch v1.1.3
...
cosmo-upgrade: upgraded; reboot to run it, then pkg update && pkg upgrade; --rollback returns to be-v1.1.2
cosmo$ cosmo-upgrade --fetch v1.1.3
...
cosmo-upgrade: the boot set on ... is already this one: finishing
cosmo-upgrade: /etc/pkg/repos.conf: the project's address moved to https://ceesafe.github.io/CosmoOS/
cosmo-upgrade: upgraded; reboot to run it, then pkg update && pkg upgrade
```

Then reboot and `pkg update && pkg upgrade`, which reads
`https://ceesafe.github.io/CosmoOS/`. A system upgraded once only keeps
the old address in `repos.conf`, which still works; any later run of the
new `cosmo-upgrade` that upgrades moves it.
`cosmo-upgrade --rollback` returns to v1.1.2, whose configuration still
names the old address, which keeps working.

Known: as in v1.1.2 (its [notes](v1.1.2.md)). To go back from OpenSSH's
`sshd` to dropbear, run `svc stop sshd` before `pkg remove
openssh-server` and `svc start dropbear`.

Tested:

- On every change, on both architectures: `make test-upgrade` upgrades an
  installed system whose `repos.conf` names the old address, and requires
  the move.
- On a Parallels virtual machine upgraded from v1.1.2 to v1.1.3-rc1,
  whose `repos.conf` named the old address, before this release was
  tagged: the first run (v1.1.2's `cosmo-upgrade`) left it, the second
  (the new one) moved it. See [Tested platforms](../guide/platforms.md).
