# ceesafec 0.37.0 to 0.48.1, 2026-11-15

The owner asked for the pin to move to CeeSafe's current release after R1's
first PR (#525) and before R1's ISO PR, whose new kernel code is CeeSafe.
The branch was made and validated with 0.47.1, the latest release then
(2026-11-14 22:50 UTC). By the time it was ready, CeeSafe had published
0.48.0 (23:16 UTC) and 0.48.1 (2026-11-15 00:45 UTC), and the owner chose
to move the pin to 0.48.1 before the PR opened.

## Scope and baseline

Branch `ceesafec-0.47.1` (its name from the first target) from main at
`9f466e70`. In scope: the pin and the places that name it. No `.cee`
source changed: the tree compiles under 0.47.1 and 0.48.1 as it stands.

## What changed

The pin, in the six places the last bump (`cbbfebb8`, 0.33.0 to 0.37.0)
changed: `scripts/cee-gen.py`'s `CEESAFEC_VERSION`, `ci/Dockerfile`'s
version and the SHA-256 of `ceesafec-linux-x64.tar.gz`
(`aea77ae3...`, checked against the release's `SHA256SUMS`), the same
SHA-256 in `.github/workflows/ci.yml`, the install lines in
`docs/build/ceesafe.md` and `docs/build/design.md`, and the history line
in `docs/roadmap-1.3.md`. Backlog SEC-15 says 0.48.1 still emits a C
string a static points to as a writable array (`native.c`'s `static
CEE_UNUSED char ceeSC_0[] = "native\000"`).

**The two failures.** Both verdicts say `timed out after 300s`, the
watchdog's `no progress for 40000 ms` and `self-test cosmofs-replay took
50403 ms` (the four-CPU boot) and `54753 ms` (`test-harness-retry`, with
`cosmofs-snap-reserved took 9039 ms (budget 8000 ms)` beside it): the
slow mode TEST-28's entry describes (8.6 to 9.1 s for
`cosmofs-snap-reserved`, 252 to 261 s of self-tests; here 245.7 and
258.5 s). `blk-irq-budget` passed in both (the next completion ready
every time, tick gaps of 7 and 10 ms), so the host did not hold a vCPU.
`test-chaos`, also four CPUs, ran in the fast mode in the same matrix
(`cosmofs-replay` 34674 ms, 195.6 s of self-tests). The one- and two-CPU
x86-64 boots took 28.6 to 29.7 s for `cosmofs-replay`, and AArch64 34.1
to 39.2 s, as under 0.37.0 and 0.47.1.

**The kernel is 0.47.1's.** Generated by each compiler from this tree's
sources, 192 of the 198 generated files (sources and headers) differ
only in their first comment (`Generated by ceesafec 0.48.1`) and five
are the same; the one other,
`kernel/ceesafe/ceesafe_rt_async.c`, adds SIGHUP to the hosted runtime's
signal handling, under `#if !defined(CEE_FREESTANDING)`. Preprocessed
with the x86-64 release kernel's flags it is the same under both, byte
for byte, and so is its object's disassembly. So the alternated boots
below, which found either mode under both 0.37.0 and 0.47.1, are of the
same kernel code, and no new comparison was run. No budget was changed.
